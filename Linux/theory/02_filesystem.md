
---
The **Linux filesystem** is the structure Linux uses to organize and access files, directories, devices, configuration, processes, and other system resources.

Unlike Windows, Linux uses **one unified directory tree** that starts at:

```
/
```

This is called the **root directory**.

---

## 1. Filesystem Structure

A typical Linux filesystem looks like:

```
/
├── bin
├── boot
├── dev
├── etc
├── home
├── lib
├── media
├── mnt
├── opt
├── proc
├── root
├── run
├── sbin
├── srv
├── sys
├── tmp
├── usr
└── var
```

Everything is organized under `/`.

For example:

```
/home/sohan/file.txt
```

means:

```
/
└── home
    └── sohan
        └── file.txt
```

---

#  Important Directories

### `/`

The **root of the entire filesystem hierarchy**.

```
/
├── home
├── etc
├── var
└── usr
```

It is different from `/root`.

---

### `/home`

Contains normal users' home directories.

Example:

```
/home/sohan
/home/alice
/home/bob
```

A user's personal files are normally stored here.

---

### `/root`

The **home directory of the root user**.

```
/root
```

Do not confuse:

```
/
```

with:

```
/root
```

`/` = filesystem root

`/root` = root user's home directory

---

### `/etc`

Contains **system-wide configuration files**.

Examples:

```
/etc/passwd
/etc/shadow
/etc/hosts
/etc/ssh/
/etc/systemd/
```

For example:

```
cat /etc/hosts
```

---

### `/var`

Contains data that **changes frequently** during system operation.

Examples:

```
/var/log
/var/cache
/var/lib
/var/tmp
```

System logs are commonly stored under:

```
/var/log
```

---

### `/tmp`

Used for **temporary files**.

```
/tmp
```

Programs and users can store temporary data here.

---

### `/usr`

Contains a large portion of **user-space programs, libraries, and supporting data**.

Examples:

```
/usr/bin
/usr/sbin
/usr/lib
/usr/share
```

---

### `/bin`

Contains essential user commands.

On many modern distributions, `/bin` is a symbolic link to `/usr/bin`.

---

### `/sbin`

Traditionally contains system-administration commands.

On many modern distributions, `/sbin` is also integrated with `/usr`.

---

### `/boot`

Contains files required for the **boot process**.

Examples include:

```
kernel
initramfs
bootloader configuration
```

---

### `/dev`

Contains **device files** representing hardware and certain virtual devices.

Examples:

```
/dev/sda
/dev/null
/dev/tty
```

Linux uses a device-file interface for interacting with many devices.

---

### `/proc`

A **virtual filesystem** that exposes information about running processes and the Linux kernel.

Example:

```
/proc/1
```

represents information associated with PID 1.

You can view system information such as:

```
cat /proc/cpuinfo
```

and:

```
cat /proc/meminfo
```

`/proc` doesn't normally represent ordinary files stored on disk; its contents are generated by the kernel.

---

### `/sys`

Another virtual filesystem that exposes information about the **kernel, devices, and hardware**.

```
/sys
```

It is primarily used for interacting with and inspecting the kernel's device model.

---

### `/run`

Contains **runtime data** created since the system booted.

Examples include:

- PID files
- Unix sockets
- Runtime state

---

### `/mnt`

Commonly used as a temporary location for **mounting filesystems**.

Example:

```
/mnt
```

---

### `/media`

Commonly used for **removable media** automatically mounted by desktop environments.

Examples:

```
/media/sohan/USB
```

---

### `/opt`

Used for **optional/additional software packages**.

For example:

```
/opt/application/
```

---

### `/srv`

Intended for **data served by system services**.

For example, a server application may store service-specific data under:

```
/srv/
```

---

#  Linux Filesystem Hierarchy

The important concept is that Linux has a **single hierarchical tree**:

```
                    /
                    │
       ┌────────────┼────────────┐
       │            │            │
     /home        /etc         /var
       │            │            │
    sohan        config        log
       │
    files
```

There isn't normally a separate filesystem tree for every disk.

A filesystem can be **mounted** somewhere within this tree.

For example:

```
/
├── home
├── etc
├── var
└── mnt
     └── usb
```

A USB filesystem could be mounted at:

```
/mnt/usb
```

and then accessed through that directory.

---

#  Files in Linux

Linux treats many different things through the filesystem interface.

Common file types include:

```
-   Regular file
d   Directory
l   Symbolic link
c   Character device
b   Block device
s   Socket
p   Named pipe
```

You can see file types using:

```
ls -l
```

Example:

```
-rw-r--r--  file.txt
drwxr-xr-x  documents
lrwxrwxrwx  link
```

The first character indicates the file type.

---

#  Absolute vs Relative Paths

### Absolute path

Starts from `/`.

```
/home/sohan/file.txt
```

It identifies the location independently of your current directory.

### Relative path

Starts from your current directory.

```
documents/file.txt
```

For example, if you are currently in:

```
/home/sohan
```

then:

```
documents/file.txt
```

refers to:

```
/home/sohan/documents/file.txt
```

---

#  Special Path Symbols

### `.`

Current directory:

```
ls .
```

### `..`

Parent directory:

```
cd ..
```

### `~`

Current user's home directory:

```
cd ~
```

For user `sohan`:

```
~ → /home/sohan
```


# Wildcards / Globbing

**Globbing** is the process where the **shell expands wildcard patterns into matching filenames or directory names before executing the command**.

Wildcards are special characters used to match filenames.

---

## 1. `*` — Match Any Number of Characters

`*` matches **zero or more characters**.

Suppose the directory contains:

```
file.txt
file.pdf
file.jpg
test.txt
test.pdf
```

Run:

```
ls *.txt
```

The shell expands it to:

```
ls file.txt test.txt
```

So `ls` receives the actual filenames, not the `*.txt` pattern.

---

## 2. `?` — Match Exactly One Character

`?` matches **exactly one character**.

Given:

```
cat.txt
car.txt
cart.txt
```

Run:

```
ls ca?.txt
```

Matches:

```
cat.txt
car.txt
```

But not:

```
cart.txt
```

because `cart` has two characters after `ca`.

---

## 3. `[]` — Character Class

`[]` matches **one character from the specified set or range**.

Example:

```
ls file[123].txt
```

Matches:

```
file1.txt
file2.txt
file3.txt
```

It does not match:

```
file4.txt
```

### Range

```
ls file[1-5].txt
```

Matches:

```
file1.txt
file2.txt
file3.txt
file4.txt
file5.txt
```

---

## 4. `[!...]` — Negated Character Class

Matches one character **not included** in the specified set.

Example:

```
ls file[!0-9].txt
```

This matches filenames where that character is not a digit.

Bash also supports:

```
[^0-9]
```

for negation.

---

## 5. `{}` — Brace Expansion

Brace expansion is technically **not globbing**, but it is commonly used alongside glob patterns.

Example:

```
echo file{1,2,3}.txt
```

Produces:

```
file1.txt file2.txt file3.txt
```

Another example:

```
echo {1..5}
```

Output:

```
1 2 3 4 5
```

The important distinction:

```
Globbing       → matches existing filenames
Brace expansion → generates strings
```

---

## 6. `*` Doesn't Normally Match Hidden Files

Suppose:

```
file.txt
notes.txt
.secret
```

Running:

```
ls *
```

normally matches:

```
file.txt
notes.txt
```

but not:

```
.secret
```

Hidden files beginning with `.` require an explicit pattern such as:

```
ls .*
```

Be careful with `.*`, because it can also match:

```
.
..
```

---

## 7. Globbing Happens in the Shell

Consider:

```
rm *.txt
```

The shell first expands:

```
*.txt
```

into matching filenames:

```
file1.txt file2.txt file3.txt
```

Then `rm` effectively receives:

```
rm file1.txt file2.txt file3.txt
```

So **globbing is primarily a shell feature**, not an `ls`, `rm`, or `cp` feature.

---

## 8. Wildcards vs Regular Expressions

They are **not the same thing**.

### Wildcards / Globbing

Used primarily by shells for filename expansion:

```
*.txt
file?.log
file[0-9].txt
```

### Regular Expressions

Used by tools such as `grep`, `sed`, and `awk` for pattern matching:

```
^user
user[0-9]+
.*\.txt$
```

For example:

```
ls *.txt
```

uses **shell globbing**.

Whereas:

```
grep '.*password.*' file.txt
```

uses a **regular expression**.
